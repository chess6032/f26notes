# Generics

- Generics allow your code to be **reusable with different data types**.
- In a language like TypeScript, which supports an `any` type, generics allow you to resue your code with different data types *while preservering strict type checking*.
- If a class, function, type, or interface use a generic, we'd call that a "*generic* class/function/type/interface."

## Inheriting from generic classes

Subclasses can specify their superclass's type parameter(s).

```ts
class KeyValuePair<V> extends Pair<string, V> { /* ... */ }
class StringPair extends Pair<string, string> { /* ... */ }
```

The same is true for interfacces that implement other interfaces.

## Constraints with `extends`

Suppose you have a function that sorts an array, and it could theoretically work on any type for which `>` is defined.

With type parameter constraints, **`A extends B` means "A is structurally compatible with B"**. That is, *inheritance is not required.*
