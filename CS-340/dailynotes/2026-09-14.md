# React

## HTML

The connection between HTML and JS is **event handling**. e.g. `onclick` or `onload` properties in element tags.

## Document Object Model (DOM)

An HTML is a tree of nested elements, starting with the root `<html>` element. The DOM data structure is that tree (I think?). **React maintains the DOM tree for you.** (It's possible to do it yourself in JS (e.g., w/ jQuery), but that's very hard. Most modern frameworks/libraries don't let you touch the DOM yourself, you write components and then the framework/library updates the DOM based on those.) 

## Traditional vs. SPA web architecture

- **Traditional**: Originally, all HTML pages were hosted on the server. Every time you clicked on a button or link, it would grab a new page from the server.
- **SPA ("Single page application")**: One HTML page is given from the server. As the user interacts with the page, the page's DOM is updated w/ JS. 
  - Now, any further requests to the server are only to query or post data (most oftenJSON)&mdash;via a web API&mdash;which may then be used to update the DOM.
  - **This is the architecture in which React operates.**

Most real systems today use a combination of the traditional & SPA architectures.

## Injecting React into your HTML

Your HTML would look something like this:

```html
<!-- index.html --> 
<body>
  <div id="root"></div>
  <script type="module" src="/src/main.tsx"></script>
</body>
```

That `"root"` div is where all the components will be added. You'll populate that div in your code:

```tsx
// main.tsx
createRoot(document.getElementById('root')!).render(
    <StrictMode>
      <App />
    </StrictMode>
);
// (Don't worry about what StrictMode is yet. But, while we're here, not that even though
// <StrictMode> tag is technically the root, people most often refer to <App /> as the DOM "root")
```

## Creating React components (JSX)

You could *manually* create each element, like this.

```tsx
React.createElement(
    "ul",
    null,
    React.createElement("li", null, "2 lb salmon"),
    React.createElement("li", null, "5 sprigs fresh rosemary")
);
```

But this is a pain. So smart people introduced JSX, which allows you to return HTML from functions. But in the end, your JSX code will be translated back into what you see above

- The code you write in a function's return is *not* HTML, it's React components. 
  - e.g., the *div* tags you make are actually React divs, not HTML divs&mdash;although React will just translate it to HTML divs.
  - To be more precise: **What is actually returned is *virtual* DOM nodes**. Remember: React handles its own virtual DOM, which it then uses to update the real DOM being displayed on the web page.
    - (This is hwo React can be so fast. React sophistically calculates how to minimize updates to the real DOM.)
- You can insert JS into JSX with `{}`.

## React hooks: setters

```ts
const [var, setVar] = useState();
```

Then, any time you use `setVar()` to update `var`, it will re-render the component. 

Would call `setVar()` like this: `setVar((var) => var + 1);`

## Component properties

Many of your components will need data to populate them with. React calls this data "properties", and in your code it will just be **parameters to your component-returning functions**.

## React routing

A "route" is the path part of a URL. With React, the different routes don't move you to different web pages, but rather load different parts of a SPA.

### Routes & Routers

- `"react-router-dom"`
- Most often, the root-level `App` component will return a Router.

Routers look something like this:

```tsx
<Routes>
  <Route path="/login" element={< Login />} />
  <Route path="/register" element={< Register />} />
  <Route path="*" element={<Login originalUrl={} />} />
</Routes>
```

- For routes that need to load a webpage, you'll set the `element` to a `<Navigate />` element.
- You'll somewhere have an "index route"&mdash;the route given for a URL with no path.
- You can substitute variable names into the `path` property by prefixing it with a `:`. 
  - e.g., `path = "/followers/:displayedUser"`. If `displayedUser` was equal to `Rizzler`, then the path would resolve to `/followers/Rizzler`.
  - I think this will pass the variable to the component as a prop? Idk.

### Outlets

Routers/routes provide content based on the URL's path. Outlets say where to render that content.
